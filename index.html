Resumen

Qué es SIHS, en corto

La coordinación de Teleinformática y la de Logística arman los horarios de sus fichas a mano en Excel, cruzando manualmente ficha, instructor, jornada y ambiente para que nada choque. SIHS automatiza justo eso: detectar y evitar cruces de instructor, ambiente, ficha, y de contenido repetido — sin cambiarle a los coordinadores su forma de trabajar. Todo lo demás del sistema (usuarios, roles, catálogos) existe para que ese único problema se pueda resolver.

Alcance

CGMLTI primero; pensado para escalar a nivel regional entre centros con la misma problemática.

Objetivo específico #3

Culminar la funcionalidad principal en los tiempos límite (máximo hasta finalizar la etapa lectiva del tecnólogo).

Fuente

Los 4 cruces que el sistema ya detecta

Resultado repetidoEl mismo resultado de aprendizaje no puede programarse dos veces para la misma ficha.
Cruce de fichaUna ficha no puede tener dos clases al mismo tiempo.
Cruce de instructorUn instructor no puede dictar dos clases al mismo tiempo.
Cruce de ambienteUn ambiente no puede usarse para dos fichas al mismo tiempo.

Fuente: entrevistas a los coordinadores de Teleinformática y Logística — ver _Docs/Documentación general/REGLAS_DE_NEGOCIO_CONOCIDAS.md. Implementado en backend/app/services/horario_service.py.

Para la sustentación

Cómo levantar el proyecto

Dos terminales, backend y frontend por separado. Necesitas Python 3.12+, Node 20+, y las credenciales de Supabase del equipo (pedirlas si no las tienes — no están en este repo).

1 · Backend

cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env   # completar con credenciales reales
uvicorn app.main:app --reload

Queda en http://127.0.0.1:8000 — Swagger en /docs.

2 · Frontend

cd frontend
npm install
cp .env.example .env   # completar con credenciales reales
npm run dev

Queda en http://localhost:5173 (o el siguiente puerto libre).

Detalle completo, variables de entorno y troubleshooting: backend/README.md y frontend/ESTRUCTURA.md.

El momento más importante

Guion para demostrar la detección de cruces

Esto es lo que responde "¿de verdad funciona?" — se puede mostrar completo en menos de 3 minutos.

  1. Inicia sesión como ana@mail.com (Coordinador) y entra a Horarios en el menú lateral.
    Ya hay clases sembradas: Carlos Lopez dicta Lunes/Miércoles 7:00-9:00am en el ambiente 1, ficha 2874521.
  2. Crea un bloque de clase nuevo desde el panel: elige resultado, instructor, ficha y ambiente de los selects (ya no es texto libre).
    Asígnalo a una celda vacía del grid — clic para pintar, Shift+clic para rellenar un rango de días.
  3. Guarda un horario que no choca con nada y muestra el mensaje verde de éxito.
    Confirma que el sistema efectivamente creó la clase — se puede revisar en /docs del backend con GET /api/v1/horarios/.
  4. Ahora provoca un cruce a propósito: crea un bloque con el instructor Carlos Lopez, mismo día Lunes, en un horario que se solape con 7:00-9:00am (ej. 8:00-10:00am), con cualquier ficha/ambiente distinto.
    Al guardar, el sistema debe rechazarlo con: "El instructor ya tiene otra clase programada en ese horario."
  5. Opcional — cruce de resultado repetido: intenta programar el mismo resultado de aprendizaje dos veces para la ficha 2874521.
    Mensaje esperado: "Ese resultado de aprendizaje ya está programado para esta ficha."
Si algo no responde en la demo Verifica que el backend esté corriendo (http://127.0.0.1:8000/api/v1/health debe responder {"status":"ok"}) y que frontend/.env apunte a ese puerto. Swagger (/docs) sirve para probar los endpoints directo si la UI falla, sin perder la demo.

Por si preguntan

Riesgos y preguntas abiertas

Mejor decir "eso lo tenemos identificado, así lo vamos a resolver" que improvisar. Detalle completo en REGLAS_DE_NEGOCIO_CONOCIDAS.md.

Datos de prueba, no reales

El proyecto se reinició hace pocos días — no hay catálogos reales de la coordinación todavía. Lo que se demuestra corre sobre un dataset sintético pequeño pero con la misma estructura que se usará con datos reales.

Historial no migrado del todo

Guardar un horario ya valida cruces contra la tabla real, pero el Historial/PDF sigue leyendo el snapshot anterior — siguiente paso documentado en el plan de integración.

Regla de instructor mañana/tarde

Se pensó como regla general, pero la entrevista de Logística la contradijo con un caso real — queda como restricción configurable a futuro, no como validación dura todavía.

Sección de estudiantes

Depende de 3 decisiones de diseño sin resolver (login del aprendiz, si "ingresar ficha" crea o solo vincula, una ficha activa o varias) — ver SECCION_ESTUDIANTES.md.
